> Написан по правилу skill'а prompt-engineer: роль → constraints → рассуждение →

> Версия v1 — 2026-07-20. Триггер: живой прогон нашёл, что загрузка файла/
> фото/аудио отсутствует ВООБЩЕ (ни `UploadFile` в `routers/`, ни `<input
> type="file">` в `webapp/src` — грепом подтверждено перед написанием этого
> промпта), хотя это базовая ожидаемая возможность любого чата с ИИ-агентами.
> Это симптом класса проблем «пробел, который никто не заметил, потому что
> смотрели по отдельным вкладкам, а не по сквозным сценариям» — этот промпт
> закрывает именно класс, не только загрузку файлов.

## Роль

Ты — инженер полного цикла продукта AI-Office (см. `CLAUDE.md`), проводящий
**сквозной функциональный аудит от иконки до сложного сценария**. Не аудит
кода ради кода — аудит того, может ли реальный пользователь довести до конца
любую разумную задачу, не упёршись в отсутствующую кнопку, эндпоинт или
логическую связь.

## Constraints

- Формат вывода: markdown-документ `docs/functional-gaps-<YYYY-MM-DD>.md`,
  каждый пункт — заголовок с эмодзи-статусом (❌ отсутствует / 🟡 частично /
  ⚠️ нелогично) + 2-4 предложения evidence (конкретный grep/файл/строка, не
  «кажется, что...») + предложение фикса одной строкой.
- Каждый пункт **обязан** быть подтверждён либо чтением кода (`Grep`/`Read`),
  либо живым прогоном (`office-real`, реальный API) — никаких утверждений
  «наверное, не реализовано» без проверки.
- Не чинить на лету во время самого прохода аудита — сначала весь список,
  потом отдельный проход фиксов (как уже делалось в этой сессии с
  production-readiness-worklist). Исключение: тривиальные однострочные
  фиксы можно копить и применить пачкой в конце того же прохода.
- Приоритизация: P0 — пользователь физически не может завершить сценарий,
  который сам продукт обещает (лендинг/онбординг/UI подразумевают
  возможность); P1 — сценарий завершим, но нелогично/не по-русски/пугающе;
  P2 — полировка, отсутствие явно не критично.
- Не расширять зону до интеграций/платежей/деплоя — они сознательно
  заглушки (см. CLAUDE.md §решение пользователя от 2026-07-20).

## Рассуждение (что значит «от иконки до сложного сценария»)

Пройти НЕ по списку файлов, а по списку **вещей, которые пользователь физически
пытается сделать**, от простейшей до самой сложной, и для каждой проверить
весь путь: иконка/кнопка в UI → фронтенд-хендлер → HTTP-эндпоинт → доменная
логика (`office/*.py`) → персистентность → что видно в ответ.

### Обязательный список сценариев (минимум, не потолок)

**Ввод от пользователя (то, что уже нашли пробел):**
1. Прикрепить файл к сообщению в личном чате с агентом (`ChatTab`/`threads.py`).
2. Прикрепить файл в общий чат офиса (`office_channel.py`).
3. Загрузить файл/фото/аудио НАПРЯМУЮ в рабочую папку тенанта, минуя чат
   (аналог drag-and-drop в файловый менеджер) — есть ли эндпоинт вообще, не
   только UI.
4. Что происходит с загруженным файлом дальше: доступен ли он агенту как
   контекст (`prompt_builder`), может ли LLM его "увидеть" (vision для фото,
   транскрипция для аудио) — или файл просто лежит мёртвым грузом на диске.
5. Ограничения: макс. размер, разрешённые типы, что показывается при
   превышении — валидация есть или нет вообще (учитывая, что `investigation.py`
   этой же сессией получил `_MAX_MESSAGE_CHARS` только для ТЕКСТА).
6. Голосовой ввод/надиктовка сообщения (STT) — есть ли хоть намёк на API
   уровне, даже если фронтенд не подключён.

**Вывод/экспорт (симметрично вводу):**
7. Может ли пользователь СКАЧАТЬ файл из рабочей папки тенанта (не только
   посмотреть код в `/api/file`, а именно скачать бинарник — картинку сайта,
   сгенерированный PDF, если такие бывают).
8. Экспорт результата целиком (лендинг как zip, отчёт как PDF) — или только
   просмотр в браузере.

**Сквозные сценарии по каждой вкладке (иконка → сложный кейс):**
9. Для каждой из 7 вкладок NavRail (Офис/Обзор/Работа/Команда/Результаты/
   Ресурсы/Настройки) — есть ли хоть один действие-кейс, где пользователь
   нажимает кнопку и явно не понимает, что произошло (нет toast/фидбека),
   или где кнопка визуально есть, но обработчика нет (`onClick={() => {}}`
   или отсутствующий проп — грепом искать пустые/заглушечные хендлеры).
10. Явно "сложные" сценарии специально: (a) клиент за один заход просит
    ОЧЕНЬ многосоставную цель (бот + сайт + CRM-интеграция одновременно) —
    справляется ли планировщик без падения; (b) клиент передумал на середине
    (сменил цель) — уже частично описано в §8 портрета, проверить именно
    UI-путь; (c) клиент прислал противоречащие друг другу указания в двух
    разных чатах — что выигрывает; (d) агент уткнулся в вопрос, а
    пользователь ушёл на 3 дня — что видно при возврате (единая точка входа
    "что важного случилось", не разрозненные вкладки).
11. Мобильная адаптивность каждой вкладки (`resize_window preset: mobile`) —
    отдельно, т.к. изометрическая сцена и плотные карточки — кандидаты на
    поломку первыми.
12. Доступность (клавиатурная навигация, focus-trap уже чинили для Modal —
    проверить остальные интерактивные поверхности: dropdown в TopBar,
    карточки инициатив, формы настроек).

### Как искать (конкретные инструменты)

- `Grep` по `onClick=\{\(\) => \{\}\}`, `TODO`, `not implemented`, `заглушка`,
  пустым `catch {}` без логирования — механические признаки недоделки.
- `Grep` по каждому фронтенд-компоненту на предмет кнопки/иконки БЕЗ
  соответствующего вызова в `api.ts` — несимметрия UI/API.
- Живой `office-real` прогон минимум одного сложного сценария (§10a) —
  не только чтение кода, чтение кода не ловит логические тупики в рантайме.
- `read_network_requests` при живом прогоне — ловит 404/500, которые UI
  тихо проглатывает.

## Примеры (формат одного пункта в итоговом отчёте)

```markdown
### ❌ P0. Нет загрузки файлов в чат
`webapp/src/app/components/RightPanel.tsx` (ChatTab) — нет `<input
type="file">`, нет drag-and-drop зоны. `routers/` — нет ни одного
`UploadFile`/`multipart` эндпоинта вообще (грепом подтверждено). Пользователь
не может прислать агенту фото витрины/скриншот конкурента/аудио голосового
брифа — приходится пересказывать текстом. Фикс: `POST /api/thread/{id}/upload`
(multipart, лимит 10MB, whitelist image/audio/pdf) → `workspace.write_file`
+ ссылка в сообщении; vision-модели уже поддержаны в `core/llm.py`
(проверить) — картинку можно сразу подмешать в контекст агента.
```

```markdown
### 🟡 P1. Кнопка «Экспортировать» в Результатах не показывает прогресс
`ResultsView.tsx:142` — `onClick={() => api.exportLeads()}` без loading-стейта,
при большом списке лидов пользователь кликает повторно, думая что не сработало.
Фикс: disabled + спиннер на время запроса (паттерн уже есть в
`SettingsView.tsx` для сохранения).
```

## Definition of done для одного прохода этого промпта

- Документ `docs/functional-gaps-<дата>.md` с полным списком, отсортированным
  P0→P1→P2, каждый пункт с evidence.
- Ничего не зафикшено молча внутри аудита — только явный отдельный шаг
  «теперь исправь по порядку», как уже принято в этой сессии.
- Каждый P0-пункт обязательно живо проверен в браузере (не только грепом),
  каждый P1 минимум прочитан в коде.
