## Основные компоненты

### 1. CEO
Главный интерфейс пользователя и управляющий всей компанией.

### 2. Decision Engine
Принимает решения на основе целей, памяти, событий и ограничений.

### 3. Отделы
Функциональные подразделения компании (маркетинг, продажи, финансы и др.), отвечающие за свои области.

### 4. Process Engine
Преобразует цели в процессы, проекты и бизнес-логику.

### 5. Workflow Engine
Разбивает процессы на последовательность действий.

### 6. Task Scheduler
Планирует выполнение задач, определяет приоритеты и очередность.

### 7. Execution Engine
Выбирает лучший способ выполнить задачу.

Способы выполнения:
- встроенная AI-модель;
- Skill (готовая бизнес-логика);
- внешний сервис или исполнитель.

### 8. Result Validator
Проверяет качество результата перед передачей его в систему.

### 9. Memory Engine
Обновляет корпоративную память после каждого действия.

### 10. Corporate File System
Хранит все знания компании:
- документы;
- процессы;
- проекты;
- инструкции;
- результаты;
- историю решений.

### 11. Business State Engine
Поддерживает актуальное состояние компании и является источником информации для принятия всех последующих решений.

## Главный принцип

AI-Office не выполняет работу самостоятельно.

AI-Office управляет цифровой компанией, которая самостоятельно планирует, делегирует, выполняет, проверяет и совершенствует свою работу, используя как встроенный интеллект, так и внешние инструменты и сервисы.




Теперь по поводу промптов

Вот здесь у меня уже есть мнение.

Я бы НЕ делал промпты внутри агентов.

Это одна из самых распространенных ошибок.

Например

MarketingAgent(
    prompt="Ты директор маркетинга..."
)

Я бы так не делал.

Потому что через год

ты захочешь изменить поведение маркетинга.

И тебе придется менять код.

Я бы ввел понятие

Role Definition

Это НЕ промпт.

Это описание роли.

Например

role:
  id: marketing_head

mission:
  увеличивать рост компании

responsibilities:

- реклама
- бренд
- аналитика

tools:

- ads
- seo
- analytics

authority:

- запускать кампании до бюджета X

constraints:

- соблюдать Конституцию

success_metrics:

- ROI
- CAC
- LTV

Это уже не промпт.

Это конфигурация роли.

А промпт должен собираться динамически.

Например

System Prompt

=

Role Definition

+

Company Philosophy

+

Company Constitution

+

Department Context

+

Memory

+

Current Process

+

Current Task

+

Current Business State

То есть модель никогда не получает один статический промпт.

Она получает контекст, собранный специально под конкретную задачу.

Тогда лидер отдела вообще ничего не пишет.

Он не "выдает промпты".

Он передает задачу.

Например

CEO

↓

"Запустить новый лендинг"

↓

Marketing Head

↓

Process Engine

↓

Skill

↓

Prompt Builder

↓

LLM

Лидер вообще не знает, какой промпт уйдет модели.

Я бы разделил это на 5 сущностей

Вместо слова "промпт".

Role

Кто я?

Policy

Что мне разрешено?

Context

Что происходит?

Task

Что нужно сделать?

Memory

Что я уже знаю?

И только потом

Prompt Builder

собирает всё это в один запрос.

Почему это важно

Потому что через год у тебя появятся:

GPT
Claude
Gemini
локальные модели

И окажется, что одним моделям нужен один формат промптов, другим — другой.

Если промпты "зашиты" в агентов, их придется переписывать.

Если есть Prompt Builder, ты меняешь только его.

На мой взгляд, правильная иерархия должна быть такой:
Company Philosophy
        ↓
Company Constitution
        ↓
Role Definition
        ↓
Department Policy
        ↓
Current Business State
        ↓
Process Context
        ↓
Task Context
        ↓
Memory Retrieval
        ↓
Tool Definitions
        ↓
Prompt Builder
        ↓
LLM

В этой схеме ни у одного отдела и ни у одного "агента" нет собственного постоянного промпта. Есть описание роли и политики, а итоговый запрос строится динамически в зависимости от состояния компании и конкретной задачи. Я считаю, что именно такой подход лучше всего соответствует той архитектуре AI-Office, которую мы с тобой проектируем.
