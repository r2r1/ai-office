СКИЛЛ: системный стек платформы для ЛЮБОГО сайта/лендинга — React + Vite +
Motion. Не выбираешь стек по ситуации — этот скилл покрывает и простой
контентный лендинг, и «вау»-сайт с 3D/анимациями (Motion входит в стек по
умолчанию, используешь её степень интерактивности по задаче).

⚠️ БИБЛИОТЕКА НАЗЫВАЕТСЯ Motion, НЕ Framer Motion: с середины 2025 проект стал
независимым и переименован (npm-пакет `framer-motion` → `motion`, импорт
`from "framer-motion"` → `from "motion/react"`). Старый пакет `framer-motion`
формально ещё работает, но БОЛЬШЕ НЕ РАЗВИВАЕТСЯ — не ставь его в новый проект.
API компонентов/хуков идентичен, поменялось только имя пакета и путь импорта.

⚠️ ПОЧЕМУ ОДИН СТЕК, А НЕ РОТАЦИЯ: раньше было 4 конкурирующих скилла (vanilla
HTML, Vue+esm.sh, Alpine+Tailwind CDN, React+esm.sh без сборки) — разброс без
пользы: разные баг-классы на каждый (Alpine — порядок CDN-плагинов, esm.sh —
рассинхрон importmap/явный импорт React), непредсказуемо для клиента, что он
получит. Один стек — предсказуемое качество и один набор проверок. Если клиент
явно попросит другой стек (Alpine/Vue/голый HTML) — это устанавливаемый скилл
клиента (skill_store), не платформенный дефолт; не предлагай их сам.

Платформа умеет собирать проект сама: ты пишешь ИСХОДНИКИ, офис запускает
npm install + npm run build и публикует результат (dist/). НЕ запускай
npm/сборку сам через execute_code — это работа платформы.

⚠️ ЕСЛИ site/ УЖЕ СУЩЕСТВУЕТ на другом стеке (легаси-проект/клиент раньше
установил свой скилл) — это ПРАВКА: сохрани стек и контент, не переписывай
сайт ради смены стека без явной просьбы.

⚠️ ЕСЛИ СБОРКА ОТКЛЮЧЕНА ОПЕРАТОРОМ ПЛАТФОРМЫ (задача/критик прямо скажут
«исполнение сборки отключено» — по умолчанию на платформе ALLOW_SITE_BUILD=0):
НЕ создавай package.json/vite.config.js вообще — npm install/build просто не
запустится, а недостроенный Vite-скелет (index.html со `<script type="module"
src="/src/main.jsx">`) в браузере НЕ РАБОТАЕТ (не JSX, не бандл — страница
пустая или белый экран, реальный прод-баг). В этом режиме пиши ПРОСТОЙ
статический сайт:
  site/index.html — HTML целиком, обычный <script> (не type="module", не JSX).
  site/styles.css — обычный CSS.
  Motion/React недоступны без сборки — анимации делай CSS
  (transition/animation/@keyframes) и IntersectionObserver в паре строк
  ванильного JS для появления при скролле — тот же эффект (1), что и выше,
  без библиотеки.
Если ранее уже начат Vite-проект (package.json/vite.config.js/src/*.jsx) и
выяснилось, что сборка отключена — не чини его точечно бесконечно: перепиши
site/index.html в статику одним файлом (сохранив контент/оффер/форму), старые
package.json/vite.config.js/src/ удали (delete_file), чтобы не путать критика
и следующего исполнителя недостроенным гибридом.

СТРУКТУРА ПРОЕКТА (всё внутри site/):
  site/package.json      — scripts.build ОБЯЗАТЕЛЕН: {"build": "vite build"}.
                           Зависимости: react, react-dom, motion (dependencies);
                           vite, @vitejs/plugin-react (devDependencies). Точные версии
                           не выдумывай — мажорные ("^18", "^12", "^5") достаточно.
  site/vite.config.js    — ОБЯЗАТЕЛЬНО base: './' (сайт хостится под
                           /site/{tenant}/{slug}/ — абсолютные /assets/ не работают):
                             import { defineConfig } from 'vite'
                             import react from '@vitejs/plugin-react'
                             export default defineConfig({ base: './', plugins: [react()] })
  site/index.html        — entry Vite (<div id="root"> + <script type="module" src="/src/main.jsx">)
  site/src/main.jsx      — маунт приложения
  site/src/App.jsx (+компоненты) — обычный JSX, `import { motion } from 'motion/react'`
                           работает из коробки (сборка есть — importmap/esm.sh не нужны).

ДИЗАЙН: палитра ДОСЛОВНО из строки «Стиль: …» в docs/site_content.md (её пишет
designer в скилле «Бренд-бук», ПОСЛЕ явного «да» владельца — см. docs/brand_book.md
за деталями палитры/приёма). Не изобретай палитру сам — read_file docs/site_content.md;
нет строки и designer в компании ещё нет (отдел не открыт) — выбери направление
из каталога скилла «Бренд-бук» сам по нише/аудитории брифа, пометь в ответе,
что это черновой выбор без утверждения владельцем.

MOTION — ПРИЁМЫ (используй по задаче: простому лендингу хватит пункта 1,
«вау»-сайту — 2-3 пункта, не все сразу на одном экране; тренд 2026 —
сдержанность, а не «мигающий» дизайн, см. ⚠️ СИГНАТУРА ниже):
1. Появление секций при скролле (scrollytelling): `whileInView={{opacity:1,y:0}}
   viewport={{once:true}}`, stagger через variants контейнера со staggerChildren —
   базовый приём, есть почти всегда.
2. Параллакс по скроллу: `useScroll()` + `useTransform(scrollYProgress,[0,1],[...])` —
   слои двигаются с разной скоростью/глубиной.
3. Tilt-карточки за курсором: onMouseMove считает rotateX/rotateY от позиции курсора
   через `useMotionValue` + `useSpring` (живая инерция, не дёрганье); `perspective`
   на контейнере включает 3D-сцену.
4. Магнитные кнопки: главный CTA слегка «тянется» к курсору при наведении —
   onMouseMove считает смещение курсора относительно центра кнопки, применяет
   через `useMotionValue`+`useSpring` к `x`/`y` кнопки (обнуляется на onMouseLeave).
   Использовать точечно — 1 главная кнопка на экран, не на каждый элемент.
5. Bento-сетка: карточки/блоки РАЗНОГО размера в одной CSS-grid (не одинаковые
   плитки в ряд) — уместна для блока «услуги»/«преимущества»/«возможности»,
   каждая карточка может иметь свой лёгкий hover/tilt.
6. spring-переходы (`type:'spring', stiffness/damping`), не линейные — ощущение "живого".
⚠️ КРИТЕРИЙ «ЭТО НЕ 3D/АНИМАЦИЯ, А ПЛАШКА»: статичный CSS `transform: rotateX(...)`
без обработчиков (mousemove/scroll) не считается — если заявляешь «3D» в тексте
страницы, нужен минимум ОДИН эффект, реально реагирующий на действие пользователя.
⚠️ respect `prefers-reduced-motion` — при включённом отключай тяжёлые анимации.
⚠️ СИГНАТУРА: не более одной крупной motion-идеи на экран (hero-сцена ИЛИ
scroll-parallax ИЛИ tilt-карточки/магнитная кнопка — не всё разом на первом
экране). Выбери одну характерную деталь ниши под приём, а не абстрактный
«летающий куб» — микро-интеракции (кнопки/форма/hover) важнее эффектных, но
пустых декораций, они прямо влияют на конверсию.

КАРТИНКИ: без внешних файлов (Unsplash и т.п. не грузятся) — SVG или CSS-градиенты.

ФОРМА ЗАЯВКИ (обязательна, иначе сайт не пройдёт приёмку):
  Компонент формы шлёт POST на /api/site-lead через fetch:
    fetch('/api/site-lead', { method: 'POST',
      headers: {'Content-Type': 'application/json'},
      body: JSON.stringify({ name, contact, message }) })
  Поле contact (телефон или email) обязательно; имя поля в state, атрибут `name`
  инпута и ключ в отправляемом JSON — ОДНО И ТО ЖЕ слово (не `phone`/`contact`
  вперемешку — иначе поле визуально не реагирует на ввод). Валидация — ТОЛЬКО
  после blur/попытки отправки, не сразу при монтировании формы. Кнопка переключает
  текст ПОЛНОСТЬЮ между состояниями (`sending ? 'Отправка…' : 'Отправить'`), не
  выводит оба состояния разом. После успеха — «Спасибо, свяжемся с вами».

ПРОВЕРКИ ПЕРЕД СДАЧЕЙ:
1. verify_code — синтаксис исходников (сборку прогонит платформа при публикации).
   Если публикация вернула «Сборка не прошла» с логом — почини ошибку в исходниках
   (read_file → write_file), НЕ переписывай проект с нуля.
2. Контент (офферы, тексты) — из docs/site_content.md от маркетолога, палитра —
   из строки «Стиль: …» там же (пишет designer, скилл «Бренд-бук»).
3. Заявляешь «3D»/«анимацию» в тексте — минимум 1 живой эффект (mousemove/scroll),
   не статичная CSS-плашка.
4. Форма реально шлёт POST /api/site-lead; ошибки не видны до первого взаимодействия;
   текст кнопки не задваивается.
5. Адаптив (мобильный viewport), respect prefers-reduced-motion.
6. `site/src/main.jsx` ОБЯЗАН импортировать стили: `import './styles.css'` (или
   как назвал файл) — реальный прод-баг: styles.css написан, но не импортирован
   нигде → Vite не включает его в бандл → собранный сайт открывается БЕЗ единого
   стиля (голый браузерный дефолт), при этом сборка проходит без единой ошибки
   (verify_code/vite build этого не ловят — файл просто не используется).

ВЫПОЛНЕНИЕ: пиши файлы через write_file. Публиковать не нужно — офис соберёт и
опубликует site/ сам. В конце ответа ОДНОЙ строкой: «Изменения: …».
