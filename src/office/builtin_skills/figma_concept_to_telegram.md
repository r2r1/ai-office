СКИЛЛ: для случая, когда владельцу НЕ нужен готовый сайт/проект — только
показать дизайн-концепт для обратной связи в Telegram-канале. Отдельный,
более короткий путь, чем «Бренд-бук → developer → сайт»: здесь нет ни
одобрения владельцем (это ЕГО инструмент получить обратную связь, не финальное
решение), ни передачи разработчику — задача закрывается самой публикацией.

КОГДА ПРИМЕНЯТЬ: владелец (или CEO по его прямой просьбе) прямо просит
«покажи макет в канале» / «выложи концепт в телеграм» — НЕ когда речь идёт
о полноценном сайте (тогда — скилл «Бренд-бук», затем сайт строит developer).

ШАГИ:
1. Figma должна быть подключена (см. list_integrations) — если нет, ask_user
   «нажми «Войти через Figma» в Доступы» (НЕ проси API-ключ — это OAuth).
2. use_integration("figma", "export_images", {file_key, node_ids, format:"png"}) —
   file_key/node_ids берутся из ссылки Figma, которую дал владелец (формат
   figma.com/file/<file_key>/...?node-id=<node_ids>). Нет ссылки — ask_user за ней.
3. Результат — ссылки вида "<node_id>: <url>". Возьми url и вызови
   use_integration("telegram", "send_photo", {chat_id, photo_url: url, caption}) —
   chat_id канала уточни у владельца, если неизвестен (@username канала или
   числовой id). Подпись (caption) — 1 короткое предложение, что это за концепт.
4. Если узлов несколько — отправь каждый отдельным send_photo (Bot API не
   поддерживает несколько фото одним вызовом без media group, которой у нас нет).

НЕ ДЕЛАЙ: не создавай Project/Task под это — это разовое действие, не веха
пути к цели (если владелец потом попросит "теперь сделай сайт по этому
макету" — вот тогда обычным порядком: designer оформляет бренд-бук с
референсом на этот Figma-файл, дальше стандартный путь).
