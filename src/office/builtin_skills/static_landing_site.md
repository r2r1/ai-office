СКИЛЛ: премиальный статический сайт/лендинг (без сборки, без 3D) — уровень студии.

ФАЙЛЫ (в site/): index.html + site/styles.css + site/script.js (стили и скрипт
ОТДЕЛЬНЫМИ файлами, не инлайном). Доп. страницы — по необходимости, общий css/js во все.
🚫 Никаких Tilda/Webflow/Wix/конструкторов — только собственный код.

ПРАВКА vs НОВЫЙ САЙТ (критично):
• Если site/index.html УЖЕ существует — это ПРАВКА: сначала read_file, меняй ТОЧЕЧНО,
  НЕ переписывай с нуля, НЕ выкидывай готовые секции, НЕ сокращай сайт.
• В конце ответа ОДНОЙ строкой: «Изменения: …» — что именно поправил.

ДИЗАЙН — ЭТО РЕШЕНИЯ ПОД КОНКРЕТНЫЙ БРИФ, НЕ ДЕФОЛТ (иначе сайт похож на любой другой):
Любой генератор дизайна без явного направления скатывается в один из трёх шаблонов —
(1) тёплый кремовый фон (#F4F1EA) с контрастным серифом и терракотовым акцентом,
(2) почти чёрный фон с одним ядовито-зелёным/алым акцентом («тёмный SaaS»),
(3) газетная вёрстка с волосяными линиями и нулевыми радиусами. Все три легитимны
ДЛЯ СВОЕГО брифа, но становятся проблемой, если берутся по умолчанию для любой ниши —
именно так получился прошлый сайт (тёмно-синий+cyan/violet «гласморфизм», под любую нишу
один и тот же). Работай в два прохода:
1. СНАЧАЛА план (коротко, в голове/черновике, не сразу код): палитра — 4-6 именованных
   hex под настроение из «Стиль: …» (не «синий», а «глубокий терракот #C4592E»); типографика
   — display-гарнитура с характером + body-гарнитура-компаньон; layout-концепция одним
   предложением + ASCII-набросок структуры; СИГНАТУРА — один запоминающийся приём
   (необычная hero-сцена, нестандартная сетка карточек, специфичный для ниши визуальный
   мотив), ради которого стоит потратить «дерзость» этого дизайна.
2. ПРОВЕРЬ план: если любая часть похожа на дефолт, который ты выдал бы для ЛЮБОЙ другой
   ниши — переделай именно её. Только после этого пиши код по плану.
Смысловая структура (нумерация 01/02/03, разделители, лейблы) должна отражать РЕАЛЬНОЕ
свойство контента (этапы работы, шаги процесса) — не декоративный шаблон без причины.
Потрать «дерзость» на ОДНО сигнатурное место; вокруг нее — дисциплинированно и тихо.
Не более одной крупной идеи движения/анимации за экран — page-load, скролл-реакция ИЛИ
hover-детали, но не всё сразу (иначе выглядит сгенерированным).

ВИЗУАЛЬНАЯ ПЛАНКА (иначе получается дёшево — так делать НЕЛЬЗЯ):
• Палитра НЕ по умолчанию и НЕ твоя зона решения — это бренд-выбор маркетинга.
  Сначала read_file docs/site_content.md за строкой «Стиль: <Название>». Найди
  ЭТО ЖЕ название в КАТАЛОГЕ НАПРАВЛЕНИЙ скилла «Продающий лендинг: структура
  под конверсию» (use_skill/find_skills по слову «стиль»/«направление», если
  плейбук не в контексте) и возьми его hex-палитру/шрифты/сигнатурный приём
  ДОСЛОВНО — не приблизительно и не «в похожем духе». Нет строки «Стиль: …» —
  ask_colleague("marketer", "нужна строка «Стиль: <название из каталога>»"), не
  придумывай палитру сам. Только если в компании нет marketer (отдел маркетинга
  не открыт) — выбери направление из того же каталога сам по нише/аудитории
  брифа и пометь в ответе, что это черновой выбор; иначе не бери дефолтный
  тёмно-синий+cyan/violet «SaaS-гласморфизм» (шаблонный вид для любой ниши).
• Дизайн-токены в :root — палитра (фон, поверхность, акцент, текст 2 уровня),
  радиусы, тени, отступы по шкале 4/8px. Единая система, не случайные значения.
• Типографика: заметная шкала (hero 44–64px, H2 28–36px, body 16–18px,
  line-height 1.5–1.7), 2 гарнитуры максимум (system-ui/Inter ок), контраст ≥ 4.5:1.
• Тёмная ИЛИ светлая тема — но целостная; фон не чисто белый/чёрный, а тон из палитры.
• Глубина: мягкие тени, тонкие рамки (1px), скругления; gradient-mesh/blur-пятна в hero
  через CSS (radial-gradient), без внешних картинок. SVG-иконки, НЕ эмодзи.
• Ритм секций: щедрые вертикальные отступы (72–120px), контент в max-width ~1100px по центру.
• Микро-взаимодействия: hover на кнопках/карточках (transform: translateY/scale + смена тени,
  transition 150–250ms ease), focus-состояния видимы. Уважай prefers-reduced-motion.
• Появление секций при скролле — IntersectionObserver (fade+translateY), 1–2 акцента, не всё подряд.
• Полная адаптивность: mobile-first, никакого горизонтального скролла, тач-цели ≥ 44px.

СТЕК — ЧИСТЫЙ VANILLA JS НЕ ОБЯЗАТЕЛЕН (частая причина «все сайты выглядят одинаково
дёшево»): платформа хостит site/ как статику БЕЗ шага сборки, но это не значит «только
голый CSS + document.querySelector». esm.sh отдаёт npm-пакеты прямо в браузер через
<script type="importmap"> — можно подключить готовую библиотеку одной строкой, без
сборщика (тот же приём, что в скилле «3D-лендинг на Framer Motion», но необязательно
для 3D). Выбирай ОДНУ, если она реально поднимает ощущение премиальности выбранного
направления стиля — не подключай все сразу:
  • GSAP + ScrollTrigger (esm.sh/gsap) — плавные scroll-анимации, параллакс, pin-секции.
  • Motion One (esm.sh/motion) — лёгкая альтернатива framer-motion для 2D-переходов.
  • Lenis (esm.sh/lenis) — инерционный плавный скролл, ощущение «дорогого» сайта.
  • Splide/Swiper (esm.sh/@splidejs/splide) — карточки-каратели для кейсов/отзывов/галерей.
Это ОПЦИЯ, а не требование: чистый CSS/vanilla JS остаётся законным выбором, если он
лучше подходит выбранному направлению (например «Газетный минимализм» — про сдержанность,
лишняя библиотека там неуместна). Не бери библиотеку «чтобы было» — решение должно
следовать из сигнатурного приёма каталога направлений, а не быть украшением сверху.

СОДЕРЖАНИЕ: минимум 5 секций (hero с чётким оффером и 1 главным CTA, преимущества/ценность,
как работает/услуги, доверие — кейсы/отзывы/цифры, контакт+форма) — это ФУНКЦИОНАЛЬНЫЙ
минимум, не жёсткий порядок/вид: см. скилл «Продающий лендинг» про то, что порядок и
подача блоков — под нишу, не под копирование. Тексты — из брифа и файлов коллег
(list_files → read_file: docs/offer.md, docs/site_content.md). Без лорем-ипсума.

ТЕКСТ НА СТРАНИЦЕ — ТОЖЕ ДИЗАЙН-МАТЕРИАЛ, не заполнитель верстки:
• Пиши со стороны посетителя: называй вещи тем, что он получает, а не тем, как это
  устроено внутри («заявка на замер», не «POST-запрос в CRM»).
  🚫 Служебные термины (/api/site-lead, «пакет упаковки», названия внутренних тулов)
  НИКОГДА не должны попасть в видимый текст страницы.
• Активный залог и конкретика вместо общих слов: не «команда профессионалов с
  индивидуальным подходом», а «12 лет монтажа потолков, гарантия 3 года на договоре».
• Кнопка называет РЕЗУЛЬТАТ действия («Получить расчёт»), не механику («Отправить»,
  «Submit»); текст подтверждения после отправки — та же формулировка результата.
• Пустые/ошибочные состояния объясняют, что случилось и что делать, а не извиняются
  и не пугают техническим текстом.

ФОРМА ЗАЯВКИ (КРИТИЧНО — без этого сайт бесполезен):
JS РЕАЛЬНО шлёт fetch('/api/site-lead', POST, JSON {name, contact, message}), с валидацией
и экраном «спасибо». 🚫 НИКАКИХ заглушек: «подключаем CRM», «готово к отправке», форма,
которая ничего не отправляет — ЗАПРЕЩЕНЫ. 🚫 Бэкенд не строй — эндпоинт уже хостится.
Стандарты фидбека формы: валидируй поле НА BLUR, не на каждый keystroke (не мешай
печатать); текст ошибки рядом с полем = что не так + как исправить, не просто
«неверно»; кнопку отправки блокируй на время запроса и показывай статус («Отправляем…»
→ «Заявка отправлена»); после ошибки сабмита фокус — на первое проблемное поле.

ОДНА СТРУКТУРА, БЕЗ ДУБЛЕЙ ФАЙЛОВ (частая беда — свалка из 20 почти одинаковых html):
Фиксированный набор: index.html + НЕБОЛЬШОЕ число именованных страниц. Правишь существующее —
сначала list_files+read_file, меняй ТОТ ЖЕ файл. 🚫 НЕ создавай варианты-клоны
(kuhnya.html, kuhnya-kmv.html, kuhnya-vannaya.html — это ОДНА страница) и заглушки
(page-2.html, landing-*.html). Все страницы связаны навигацией; index ссылается на реальные.

ПРОВЕРКИ ПЕРЕД СДАЧЕЙ:
1. Каждый файл записан через write_file с непустым путём; css/js подключены.
2. Есть дизайн-токены, единая типо-шкала, hover/focus, адаптив без горизонт. скролла.
3. Форма РЕАЛЬНО шлёт POST /api/site-lead (fetch, НЕ заглушка) и показывает подтверждение.
4. Нет файлов-дублей и пустых заглушек; страницы связаны навигацией.

ВЫПОЛНЕНИЕ: пиши файлы через write_file. Публиковать не нужно — офис опубликует site/ сам.
